# Third-party harness cost inputs
## Scope
Approved revisions to [warp#16240](https://github.com/warpdotdev/warp/pull/16240) and [warp-server#18837](https://github.com/warpdotdev/warp-server/pull/18837). The [full approved specification](https://staging.warp.dev/drive/notebook/hfN0JcNfEzOOBMnRrcD3gZ) is authoritative.
Estimate current public-list-price dollars from native Claude Code and Codex response usage. This is not a provider invoice or a Warp billing change. No request ledger, threshold-rule identity/version, historical dollar-rate registry, child-discovery expansion, UI redesign, or backfill is included.
## Wire contract
Publish `snapshot.payload.format: "cost_inputs_v3"`. The server retains `metricsVersion: 3`; publication identity remains positive signed-64-bit execution/sequence plus read-start RFC3339 timestamp.
The payload has independent optional siblings, omitted rather than null:
* `cost_metadata: {groups: [...]}` contains at most 128 homogeneous concrete-model/service-tier/inference-geo/speed groups.
* `output_tokens` is a nonnegative signed-64-bit reporting total, independent of cost-band output.
* `toolCalls: {total, byName}` contains independently deduplicated invocation counts.
Each cost group requires `model`, optional modifiers and positive `long_context_threshold_tokens`, and at least one native `pre_threshold` or `post_threshold` usage band. Absence of the cutoff means an explicitly known no-threshold model; it does not mean unknown policy. Such models have no post band. Duplicate effective group keys, mixed legacy shapes, unknown fields, and nulls are rejected.
Coverage independently declares cost `known|unavailable`, output `known|partial|unavailable`, and tools `known|partial|unavailable`. Known cost requires its object; unavailable forbids it. Known/partial reporting requires its counter; unavailable forbids it. A diagnostic-only unavailable snapshot replaces stale retained cost. Complete measured empty history has empty groups and zero counters.
Codex bands require input, cached input, cache-write input, and output. Input includes caches; output includes reasoning. Cache reads+writes cannot exceed input. Optional reasoning/total counters are retained only when every member supplies them; reasoning cannot exceed output, and total equals input+output when supplied.
Claude bands require uncached input, cache reads, aggregate writes, and output. Nonzero writes require both 5-minute and 1-hour partitions, whose checked sum equals aggregate writes.
Use checked signed-64-bit arithmetic, including values above 2^53. Any incomplete input, attribution, policy, reconciliation, arithmetic or cost bound disables the entire cost object; trustworthy output/tools survive independently. Skipped native records or extraction limits mark affected retained reporting partial; absent trustworthy measurement remains unavailable. A cost-only group bound does not downgrade complete reporting. At the 129th cost key release all cost aggregates, not a prefix. Repeated responses in an existing key consume no additional wire capacity. Drop the entire cost object if encoding exceeds 1 MiB; if reporting alone exceeds that cap, diagnose nonpublication rather than truncate.
## Per-capture metadata and capture
The existing transcript-target response flattens unchanged upload fields and adds optional `threshold_policy: {schema_version: 1, models}`. The map associates normalized concrete model IDs with `{kind: "input_gt", tokens}` or `{kind: "none"}`. It contains no rates, rule ID, or rule version. Bounds are 128 models, 256-byte keys and 64 KiB.
The server derives the full model map from its current pricing catalog for each upload target, after existing authorization and conversation binding checks. It does not persist a conversation policy. Later captures in the same conversation may classify differently when the catalog changes; a single capture and its publication retries retain one coherent policy.
The client fetches metadata before allocating capture identity and reading native history. Parse policy independently from the target: missing, malformed or unsupported policy disables cost only. Never guess a local cutoff. Raw bytes and usage derive from the same capture; only successful raw upload enables metrics publication. Retries preserve bytes, sequence and timestamp, and metrics retry never mints a target.
Classify each deduplicated response with strict native input `> cutoff`; equality is pre. Codex uses native input, Claude uncached input+reads+aggregate writes. Never threshold an aggregate: ten 100K responses remain standard even when their pre-band sum exceeds 272K.
## Native extraction
Codex uses `token_usage_record.usage`, deduplicated by response identity and compatible thread/turn/session/root ownership. Join matching turn model and thread-owned settings tier, not the final run-wide model. Reconcile native turn/thread totals. Compaction copies cannot recover missing earlier responses; conflicting identities or uncovered baselines disable cost. Checkpoints never become inferred requests. Synthetic active-context estimates do not add billable usage.
Claude preserves session/message streaming reconciliation, captured-subagent scope, and independent tool deduplication. Synthetic/error records and compaction markers are free; real summarization responses count once. Compaction does not reset billable history.
## Pricing and consumers
Validate published structure and counters, not agreement with today's cutoffs. Price the recorded bands even when their cutoff differs from the current catalog. Keep existing identity ordering and whole-snapshot replacement: valid newer unavailable snapshots replace stale known data; malformed publications do not. Retain deployed v1 reporting compatibility and grouped v3 only; v1 provider estimates are unavailable.
Resolve recorded pre/post bands with an explicit standard/long-context rate selector. Never call a request-price helper with aggregate input or a fabricated threshold+1. Missing post/category rates or unsupported model/modifier suppress the whole estimate, never a priced subset or zero contribution. Current rates may change deliberately; historical dollar-rate stability is deferred.
Codex subtracts reads from base input and subtracts writes only when a separate write rate applies; reasoning/total add no charge. Claude TTL partitions replace aggregate writes. Preserve existing flex/priority/batch/fast and defined US modifiers; unknown nonneutral values fail pricing.
Third-party inference remains optional through run metrics, attempts, benchmark configurations/rollups, judge facts, API serializers and mirrored consumers. Totals sum available components, independently of aggregate inference completeness: $2 compute + $1 platform + $5 known inference yields $8 even with another unknown inference contributor. Preserve compute/platform breakdowns and distinguish absent inference from measured zero. Do not add a completeness flag or partial-total UI. Retain all-attempt retry totals, completed-attempt success averages, conversation deduplication, system/judge exclusions, separate scoring charges, provider-estimate fallback and missing/truncated-tree or no-dollar-data safeguards. Judge cost facts describe recorded charges plus available public-list-price provider estimates, potentially excluding unknown spend. Oz credits and billing are unchanged.
## Rollout and verification
Deploy server metadata, v1/v3 decoders/storage, estimator and optional-inference consumers before the client. No policy migration or pin initialization is required. Stop v3 producers before rollback and retain v3 reader support.
Verification covers native/reconciliation, threshold/cache/modifier, 128/129-group, 10,000-response, 1 MiB, metadata/auth/ordering/retry, unavailable replacement, mixed available-spend aggregation/judge and legacy/Oz behavior. Rust and Go consume identical complete-Codex, complete-Claude, aggregate-only, unavailable, measured-empty and mixed-format fixtures.
Run focused harness/publication tests and Clippy, affected Go packages and vet/lint, generated DTO consistency, and applicable frontend checks. Visual verification is not claimed.
