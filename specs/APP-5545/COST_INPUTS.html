THIRD-PARTY HARNESSES · CLIENT + SERVER · CONTRACT SPEC

Harness cost inputs: complete or omitted

The proposed wire object and native transcript → server estimate flow.

2026-10-07 · engineering review · warp@0ae320fa1e · warp-server@5a40cefedb

The contract in one glance

Complete cost inputs, or no cost estimate. Reporting survives independently. Native Codex records remove checkpoint-boundary inference for fully covered response histories. This revises warp#16240 and warp-server#18837; it does not implement them.

01 · Price inputs

cost_estimation?
All per-response usage + classifications. No remainder.

02 · Output

output_tokens?
One independent aggregate. Never counted twice.

03 · Tools

toolCalls?
One count + name map. No request-level tool metrics.

Draft for approval Public list-price estimate No Codex upgrade needed

What is parsed → what is priced

Exact native-record rules and scope
  • Codex: take usage once per compatible response identity. Join its matching turn model; configured tier comes from event_msg / thread_settings_applied / thread_settings.service_tier, not turn_context. Use native turn/thread totals only to detect uncovered history or conflicts, within matching ownership/lineage.
  • Compaction: deduplicate compacted.latest_token_usage_record copies. The marker and synthetic context-size updates are not charges. A real completed summarization response is. Never reset billable totals at a compaction boundary.
  • No cost fallback: legacy or mixed history lacking complete native records gets no cost inputs. Reporting output may use an unambiguous additive legacy checkpoint instead of overlapping native totals; otherwise retain only a safe partial response sum. Never sum checkpoint and native copies.
  • Claude: reconcile streaming copies by session/message ID, independently deduplicate tool-use IDs, and ignore synthetic/error messages. Preserve root plus captured subagent processing.
  • Scope: retain the existing Codex root-only and Claude root/captured-subagent scope. “Complete” means within that capture contract, not all provider activity. A known capture hole invalidates cost. Child discovery and invoice/rerouting precision are not added here; Codex model/tier context can be configured intent.

Field / categoryNormative rule
formatRequired literal cost_inputs_v3, even when cost is absent. It selects the contract, not a parser release.
cost_statusknown iff complete cost inputs are present; otherwise unavailable. Never partial cost. Server price lookup can still fail.
output_token_status
tool_status		Each is known, partial, or unavailable. Known/partial requires its aggregate; unavailable forbids it.
Envelope + countsKeep positive int64 execution/sequence and RFC3339 capture time. Counts are nonnegative int64 with checked sums, including >253. Zero is measured; omitted is unknown. Reject nulls and unknown fields.
Request rowRequired concrete model and native usage; optional service_tier, inference_geo, speed. Absent modifiers keep existing standard/global/nonfast defaults. Carry known nondefaults; unknown values fail pricing.
Codex usageRequired input, cached input, cache-write input, output. Optional reasoning and total. Cache reads + writes ≤ input; reasoning ≤ output; input + output = total when present.
Claude usageRequired input, output, cache-read and aggregate cache-creation. For nonzero writes, require both TTL partitions and their exact sum. No assumed 5-minute remainder.
Cost rows + tools0–4,096 complete request rows. Empty means established empty history, not extraction failure. toolCalls.total equals the checked sum of byName. IDs remain client-local.

These three metrics are top-level siblings within the existing payload. Output repeated inside a cost row is needed for pricing, but only the sibling aggregate is used for output reporting.

The extractor returns a structured cost error alongside reporting results (IncompleteInput, InvalidData, AmbiguousAccounting, or ResourceLimit). Bounded diagnostics stay local; they are not a whole-report HTTP failure. Wire coverage communicates availability.

Permit this unavailable snapshot under the same capture ordering. A newer incomplete snapshot replaces the old whole snapshot; never reuse a prior complete estimate for newer output. This intentionally replaces the previous “only successful snapshots” requirement when current availability must be represented.

Server resolution: all rows, or no estimate

Resolve the concrete model through the existing explicit map and public list-price table. For every row, select request-local rates and supported tier/geo/speed modifiers. Only after every row prices successfully, return the decimal sum. Missing inputs or one unknown price returns unavailable—not a zero contribution.

Carry “unknown” through every consumer

Provider/inference and total estimated-dollar values become optional through run metrics, benchmark attempts/configurations/run rollups, and judge facts. If a contributing cost is unavailable, the total/average is unavailable; never sum only known attempts or show Warp-only dollars as a complete total. Compute/platform dollars and credits remain known. Oz is unchanged.

Read output and tools from their payload siblings, even when no estimate exists. The cost result is a typed optional decimal plus a bounded error; absent optional dollar fields are omitted in responses.

Category formula and supported classifications
  • Codex: subtract cache reads from base input; subtract cache writes only when a separate write rate applies. Price the remaining input, cached reads, separately priced writes, and output once. Otherwise writes stay at the base input rate. Reasoning and total tokens do not add charges.
  • Claude: price uncached input, cache reads, 5-minute writes, 1-hour writes, and output once. The TTL partitions replace aggregate writes; never add both.
  • Preserve the existing supported modifiers: Codex flex ×0.5, priority/fast tier ×2; Claude batch ×0.5, fast speed ×2; us geo uses the model’s surcharge where defined. Absent/default/standard tiers, global geo, and standard speed are neutral. Other nonempty classifications are unsupported and suppress the estimate.
  • Update dollar serializers, mirrored consumer types, and formatters for omission. An unavailable estimate uses the existing unavailable-value presentation, not zero; exclude unavailable values from plotted cost points without silently recomputing a rollup or average over a smaller subset.

Changes to the two PRs

Client · warp#16240

Native Codex rows + context/tier joins.
Independent output/tool aggregation.
Whole-object cost omission and per-category errors.
No remainder or cost-prefix compaction.

Server · warp-server#18837

OpenAPI/DTOs + v3 validation/read/storage.
Strict optional estimator.
Aggregate reporting adapters.
Unavailable dollars through consumers/rollups.

Keep: authorization, sequence/time/idempotence, exact retry bytes, one cumulative JSONB replacement. No per-request database ledger.

Compatibility and release order
  • Ship server v3 decoding, storage, validation, read conversion and consumers first, then the client. Unknown-field validation makes a client-first rollout unsafe. Stop v3 producers before a server rollback.
  • Retain v1 grouped and v2 request formats for old producers/storage. Their provider estimate is unavailable because they do not establish v3 completeness. Keep existing legacy output/tool adapters; never reconstruct guessed request rows.
  • Stored/read v3 envelopes use metricsVersion: 3 and existing camelCase identity names. Coverage becomes costStatus, outputTokenStatus, toolStatus. Payload and native usage names are exactly those shown above. The POST has no server-owned metricsVersion.
  • The required format marker prevents a cost-absent v3 payload being mistaken for legacy tool-only data. Reject mixed shapes and version/payload mismatch.
  • No Docker bump, billing change, historical backfill, child-rollout discovery, or UI redesign. Existing price/default assumptions remain list-price estimates, not invoice guarantees.

Acceptance checks · required, not yet run
  1. Wire fixtures: complete Codex/Claude, aggregate-only, all-unavailable, true-empty, zero vs missing, >253, null/unknown/mixed-shape rejection; Rust and Go agree.
  2. Identity/history: equal-size distinct native responses, native + checkpoint overlap, compatible copies and compacted latest-record copies, conflicts, model/tier switches, missing response usage, uncovered cumulative baseline, legacy-only and partial capture.
  3. Claude/compaction: streaming revisions, subagents, missing TTL split, synthetic markers vs actual summarization usage; no billing reset or double count.
  4. Bounds: 4,096/4,097 rows and 1 MiB; no priced prefix, aggregates survive. Own identity/input/overflow limits degrade affected categories, not fabricated values. Raw saving remains independent.
  5. Pricing: each model threshold −1 / exact / +1; same aggregate but different request distributions; unknown model/classification or missing nonzero-category rate suppresses the whole sum; true-empty differs from unavailable.
  6. Storage/consumers: newer incomplete snapshot clears older cost, stale/retry rules hold, output/tool reporting survives; unknown total propagates across attempts/rollups/judges; legacy and Oz regression cases.
