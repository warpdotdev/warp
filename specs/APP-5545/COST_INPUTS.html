THIRD-PARTY HARNESSES · CLIENT + SERVER · CONTRACT SPEC

Harness cost: client threshold aggregates

Parse individual responses locally; send only pre/post pricing usage and independent reporting.

2026-10-07 · engineering review · warp@0ae320fa1e · warp-server@5a40cefedb

Parse requests. Persist only aggregates.

The client understands thresholds; the server understands dollar rates. Deduplicate each native response, assign its pricing band, then sum native counters. Only compact aggregates cross the wire. Cost remains complete-or-omitted; output and tools remain independent.

Where each operation belongs

Exact native-record rules and scope
  • Codex: take usage once per compatible response identity. Join its matching turn model; configured tier comes from event_msg / thread_settings_applied / thread_settings.service_tier, not turn_context. Use native turn/thread totals only to detect uncovered history or conflicts, within matching ownership/lineage.
  • Compaction: deduplicate compacted.latest_token_usage_record copies. The marker and synthetic context-size updates are not charges. A real completed summarization response is. Never reset billable totals at a compaction boundary.
  • No cost fallback: legacy or mixed history lacking complete native records gets no cost inputs. Reporting output may use an unambiguous additive legacy checkpoint instead of overlapping native totals; otherwise retain only a safe partial response sum. Never sum checkpoint and native copies.
  • Claude: reconcile streaming copies by session/message ID, independently deduplicate tool-use IDs, and ignore synthetic/error messages. Preserve root plus captured subagent processing.
  • Scope: retain the existing Codex root-only and Claude root/captured-subagent scope. “Complete” means within that capture contract, not all provider activity. A known capture hole invalidates cost. Child discovery and invoice/rerouting precision are not added here; Codex model/tier context can be configured intent.

Codex v0.159.3 already contains native response records; no Docker bump is needed. Current extraction: crates/warp_harness_usage/src/codex.rs:196–208; crates/warp_harness_usage/src/claude.rs:86–95.

Two bands per pricing group—not two for the whole run

Group by (model, service_tier, inference_geo, speed), with canonical neutral defaults. Each group holds up to two independent native usage objects. Never mix model prices, modifiers, or bands.

Field / invariantNormative rule
formatRequired cost_inputs_v3. This unreleased v3 means aggregate groups only; reject requests, legacy usage/remainder fields and mixed shapes.
threshold_policy_versionRequired immutable client-catalog ID, 1–64 ASCII characters, including cost-unavailable reports. Freeze per conversation.
cost_statusknown requires the entire cost object; unavailable forbids it. Never partial cost. Rate resolution may still fail server-side.
Output/tool coverageEach is known, partial, or unavailable. Known/partial requires its sibling value; unavailable forbids it.
Group shapeRequired concrete model; optional modifiers with existing neutral defaults. Required at least one nonnull pre/post usage object. Omit empty bands. Reject duplicate effective keys.
CutoffOptional positive int64. Absent explicitly means a known no-threshold model and forbids post. Never compare a band’s cumulative input with this cutoff.
Codex usageInput, cached input, cache-write input and output required. Optional reasoning/total counters appear only if every member supplied them. Reads + writes ≤ input; reasoning ≤ output; input + output = total when present.
Claude usageInput, output, reads and aggregate writes required. Nonzero writes require both TTL partitions with their exact sum. The split replaces aggregate writes when pricing.
Counts & emptyChecked nonnegative int64, including >253. Validate each response before summing and the bands afterward. Unknown required counters are not zero. groups: [] means complete empty history; cost is $0.
Envelope & toolsKeep positive int64 execution/sequence and RFC3339 capture time. Tool-name counts sum exactly to total. Null/unknown fields are rejected. IDs stay client-local.

cost_estimation, output_tokens, and toolCalls are siblings within the existing payload. Output inside cost bands is priced once; reporting reads only its independent sibling.

Explicit server rate selection · no threshold lookup on summed usage
  • Add an explicit selector such as ListPriceForBand(modelId, Standard | LongContext). Pre uses base rates; post uses the long-context rate object directly. Never pass a summed input or fabricated cutoff+1 to ListPriceForRequest.
  • Apply supported tier/geo/speed modifiers within each group. Missing long-context rates, a nonzero category rate, model or modifier suppresses the whole dollar estimate. Never fall back from post to standard.
  • Codex base input excludes cached reads; exclude writes only if separately priced. Price reasoning inside output, not again.
  • Claude prices uncached input, cache reads, 5-minute writes, 1-hour writes and output once. Preserve existing modifiers: Codex flex ×0.5, priority/fast tier ×2; Claude batch ×0.5, fast speed ×2; US geo at the model’s defined surcharge. Known nondefaults must be carried; unsupported values fail pricing.
  • Use decimals without per-request rounding. The server validates structure/arithmetic and trusts the client’s request-local classification; compact aggregates cannot independently prove individual band membership.

Existing request-local selector: logic/ai/llm/llm.go:1816–1841. Keep that API’s behavior for its existing callers; add the band path for this estimator.

Keep old thresholds without building old dollar catalogs

Frozen

Client policy ID, effective cutoffs, and the recorded band membership of the conversation.

Explicitly deferred

Historical dollar-rate stability. The server still uses its current standard/long rate objects.

  1. First accepted v3 report: pin its client policy ID, even when cost inputs are unavailable. Before any accepted report there is no historical estimate to preserve.
  2. Follow-up/resume: add optional harness_usage.threshold_policy_version to the existing resolve-prompt capability. Return the retained pin, not today’s default. Same-process follow-ups retain the selection; a new producer uses the returned archived catalog or, with no pin, its current catalog.
  3. Policy unavailable: an unknown returned version makes cost unavailable, not silently reclassified. Output/tools and raw transcript saving continue. Missing usage capability still disables publication.
  4. Persistence: add server-owned thresholdPolicyVersion to the retained envelope, equal to v3’s payload ID. Preserve it on unavailable and legacy v1/v2 replacements. Ignore stale reports by existing ordering first; reject a newer v3 pin change. Copy the existing pin before canonical encoding and idempotence comparison.

Reparse the full native history under the pinned rule; never add retained server aggregates to freshly parsed totals. A client update changes the default for new conversations, not old conversations. The cutoff in a group is descriptive provenance; server rates are selected by the recorded pre/post slot.

No new RPC or GCS fetch is needed: extend the existing startup response with one small metadata scalar. The immutable threshold catalog lives client-side; the server stores/returns its identity.

Bound groups, not the number of requests on the wire

Proposed safety defaults: at most 128 distinct pricing groups (up to 256 band objects) and the existing 1 MiB encoded publication cap. 10,000 responses using one pricing key still need only one group.

Unknown is not zero

Carry optional provider/inference and total estimated dollars through run metrics, benchmark attempts/rollups and judge facts. A contributing unavailable cost makes the total/average unavailable. Do not sum only known attempts. Compute/platform dollars and credits remain known; Oz is unchanged.

Compatibility & release order
  • Ship server decoding, storage/read conversion, policy handoff, band selection and nullable consumers first; then the client.
  • Retained v3 uses metricsVersion: 3 and existing camelCase envelope/coverage keys. Keep thresholdPolicyVersion even on later legacy replacements. POST payload/native field names remain as shown.
  • Keep v1/v2 readers/producers and reporting adapters; their provider cost is unavailable under this strict contract. Never guess bands from legacy grouped totals. Reject per-request v3 shapes.
  • Rollback needs stopped v3 producers and a reader compatible with already retained v3/pin fields.
  • No Codex Docker bump, server transcript parsing/finalization, billing change, UI redesign, backfill, child-discovery expansion or historical dollar-rate catalog.
Implementation acceptance checks · required, not yet run
  1. Wire: shared Rust/Go complete Codex/Claude, reporting-only, all-unavailable and empty fixtures; zero/absent, >253, overflow, null/unknown/mixed shapes, duplicate effective keys, no-threshold post rejection.
  2. Parsing: native/checkpoint overlap, equal-size distinct responses, compacted latest-record copies, model/tier changes, conflicts, capture holes; Claude streaming/subagents/cache TTL. Real compaction response counts once; synthetic context updates do not. No request rows or identities in publication.
  3. Grouping: cutoff −1 / exact / +1 and both native input formulas; no threshold vs unknown rule; 10 × 100K stays standard despite 1M cumulative input; separate modifiers/models; optional Codex counters require all members.
  4. Bounds: 128/129 distinct groups, 10,000 responses in one key and 1 MiB; no priced prefix; independent output/tools and raw outcomes survive when trustworthy.
  5. Pricing: compare aggregate decimal results with per-response reference prices under the same rule/rates, including caches/TTL and modifiers. Change today’s cutoff and confirm stored bands do not move. Missing post/category rates suppress the whole estimate. For the complete Codex fixture above, assert $1.8025.
  6. History/storage: first pin, same-process follow-up, new-execution resume after catalog change, unknown archived policy, rejected pin mutation, stale/idempotent captures and unavailable/legacy replacements retaining the pin.
  7. Consumers: output/tools survive no cost; unavailable attempts/totals/averages/judges remain unavailable; legacy and Oz regression cases.
