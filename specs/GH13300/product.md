# Product Spec: Prevent false positive secret redaction warnings for MCP server configs

**Issue:** [warpdotdev/warp#13300](https://github.com/warpdotdev/warp/issues/13300)  
**Status:** In Review  
**Figma:** None (Behavioral validation fix)  

## Summary

When adding or editing a Model Context Protocol (MCP) server configuration in Warp (**Settings > MCP Servers > Add New MCP Server**), pasting or saving a valid server configuration containing local or remote network URLs (e.g. `http://127.0.0.1:29979/mcp`, `http://0.0.0.0:8000`, `http://[::1]:8080/mcp`) triggers a false positive error warning:
> *"This MCP server contains secrets. Visit Settings > Privacy to modify your secret redaction settings."*

This blocks developers from adding local MCP servers generated by Warp or common MCP harnesses. This specification defines the product behavior to ensure valid network endpoints (IPv4 and IPv6 addresses) in MCP server configurations are recognized as valid connection endpoints rather than sensitive secrets, while preserving strict redaction for actual credentials and tokens.

---

## Problem Statement

Warp provides a Secret Redaction engine (**Settings > Privacy > Secret redaction**) that scans text across the application to prevent sensitive credentials from leaking to cloud services or logs. The default recommended patterns include `IPv4 Address` and `IPv6 Address` matchers.

When saving an MCP server, Warp scans the templatable MCP server JSON for secrets via `detect_secrets_in_templatable_mcp_server`. If secret redaction is enabled (either user safe mode or enterprise-enforced), any pattern match in the JSON blocks the save. 

Because local MCP servers (such as SSE or HTTP transport servers) inherently run on loopback IP addresses (like `127.0.0.1`), the redaction scanner falsely flags the host IP as a secret credential. Users are unable to save working MCP servers without completely turning off global secret redaction across their entire terminal.

---

## Goals

1. **Permit Valid Network Endpoints**: MCP server configurations containing IPv4 or IPv6 addresses (e.g., in URLs, hosts, or CLI arguments) must be accepted and saved without false-positive secret warnings.
2. **Preserve Credential Protection**: Real credentials (such as OpenAI/Anthropic API keys, GitHub personal access tokens, AWS IDs, Slack tokens, JWTs, Stripe keys, and custom user secret patterns) embedded in MCP configurations must continue to be blocked when secret redaction is active.
3. **Zero Configuration Burden**: Developers should not be forced to disable global secret redaction or delete the recommended IP address regex from **Settings > Privacy** to use local MCP tools.
4. **Transparent Validation**: If an MCP configuration contains an actual credential alongside an IP address, saving must still be blocked with the appropriate warning.

---

## Non-Goals

1. Changing terminal grid secret redaction behavior: Terminal output redaction in active terminal sessions is unaffected by this change.
2. Modifying the user's custom secret list in **Settings > Privacy**: Users retain full control over their configured redaction patterns.
3. Validating the reachability of the MCP server network endpoint (handled by MCP runtime connection probes, not static validation).

---

## User Experience

### 1. Happy Path: Localhost / Local Network MCP Server
1. User navigates to **Settings > MCP Servers > Add New MCP Server**.
2. User enters or pastes an MCP configuration pointing to a local HTTP endpoint:
   ```json
   {
     "local_paper": {
       "type": "http",
       "url": "http://127.0.0.1:29979/mcp"
     }
   }
   ```
3. User clicks **Save**.
4. **Result:** The configuration is saved successfully; the MCP server card appears in the list. No error toast is displayed.

### 2. Happy Path: CLI Command with Host Binding Arguments
1. User pastes a CLI-based MCP server:
   ```json
   {
     "uvx_server": {
       "command": "uvx",
       "args": ["mcp-server", "--host", "0.0.0.0", "--port", "8080"]
     }
   }
   ```
2. User clicks **Save**.
3. **Result:** Saved successfully without warnings.

### 3. Edge Case: MCP Configuration with Real Credentials
1. User enters an MCP configuration containing a hardcoded API token in environment variables or headers:
   ```json
   {
     "github": {
       "command": "npx",
       "args": ["-y", "@modelcontextprotocol/server-github"],
       "env": {
         "GITHUB_PERSONAL_ACCESS_TOKEN": "ghp_123456789012345678901234567890123456"
       }
     }
   }
   ```
2. User clicks **Save** while secret redaction is enabled.
3. **Result:** Save is blocked. The error toast appears:
   > *"This MCP server contains secrets. Visit Settings > Privacy to modify your secret redaction settings."*

### 4. Edge Case: Mixed IP Address and Real Credential
1. User enters an MCP configuration with both an IP address URL and an API key:
   ```json
   {
     "custom_gateway": {
       "type": "http",
       "url": "http://192.168.1.100:8000/mcp",
       "headers": {
         "Authorization": "Bearer sk-proj-123456789012345678901234567890123456789012345678"
       }
     }
   }
   ```
2. User clicks **Save** while secret redaction is enabled.
3. **Result:** Save is blocked because the OpenAI key is an active secret credential.

---

## Testable Invariants

1. **INV-1 (IPv4 Loopback / LAN URLs Allowed):** An MCP server configuration containing IPv4 addresses (`127.0.0.1`, `0.0.0.0`, `192.168.x.x`, `10.x.x.x`) and no secret credentials is not classified as containing secrets.
2. **INV-2 (IPv6 Endpoints Allowed):** An MCP server configuration containing IPv6 addresses (`::1`, `2001:db8::1`) and no secret credentials is not classified as containing secrets.
3. **INV-3 (Real Credentials Blocked):** An MCP server configuration containing supported secret tokens (e.g. GitHub PAT, OpenAI key, AWS Access ID, Anthropic key, Stripe key, JWT) is classified as containing secrets and blocked when redaction is active.
4. **INV-4 (Mixed Endpoints with Secrets Blocked):** An MCP configuration containing both an IP address and a real secret token is classified as containing secrets.
5. **INV-5 (Redaction Disabled Passthrough):** When safe mode and enterprise redaction are both disabled, any MCP configuration can be saved regardless of content.

---

## Success Criteria

- Adding an MCP server with `http://127.0.0.1:29979/mcp` succeeds with zero errors when Secret Redaction is enabled in default settings.
- Unit tests cover IPv4, IPv6, real tokens, and mixed scenarios.
- Zero regressions in existing `should_block_save_for_secrets` test matrix.
