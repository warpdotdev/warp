# Полное удаление ИИ и входа в Warp из Rust-версии

## Что должно остаться

Rust-приложение запускается с чистым профилем и без сети. Сохраняются редактор команд, обычные shell-подсказки из истории, файлов, флагов и встроенных сигнатур, история по стрелкам, блоки вывода, вкладки, панели, поиск, настройки, темы, локальные файлы и локальные сценарии команд. Сохраняются PTY, `vim` и другие интерактивные программы, Warpify для SSH и вложенных оболочек, локальный TUI, служебные CLI-команды и Dock Tile. В терминале по-прежнему можно вручную запускать сторонние программы.

Убирается собственный ИИ Warp и специальная интеграция с внешними ИИ-инструментами. Убирается вход в аккаунт Warp и функциональность, которой требуется его облачный сервер. Системный SSH, проверка ключей хоста, `ssh-agent`, TLS, локальные проверки прав и подпись приложения остаются. Отдельный проект `macos-swift` и установленный оригинальный Warp остаются за пределами изменений. Аудит относится к текущему дереву и выпускаемым файлам. История Git и данные оригинального Warp сохраняются.

## Результаты проверки текущего дерева

| Где остался код | Что подтверждено |
| --- | --- |
| `app`, `crates/warp_tui`, общие модели | ИИ импортируется редактором, моделями блоков, терминальной сессией, восстановлением вкладок, GUI и TUI. Часть функций скрыта флагом `local_terminal`. В дереве зависимостей macOS ARM64 с этим флагом присутствуют `ai`, `ai_types`, `mcp`, оба классификатора ввода, `computer_use`, `warp_multi_agent_*`, `firebase` и оба серверных клиента. |
| `crates/warp_cli`, `crates/warp_terminal`, `crates/warp_ripgrep`, `crates/warp_completer` | Сервер PTY и служебный поиск используют аргументы общего CLI. Автодополнение строит сигнатуры из его полного дерева команд, включая ветки Oz. |
| `crates/remote_server`, `app/src/remote_server`, `script/deploy_remote_server*` | Warpify проверяет удалённый исполняемый файл через `--version`. Имя берётся из CLI канала. Для некоторых каналов установка скачивает CLI-архив, а для OSS используется заранее развёрнутый файл. Удалённый протокол содержит сообщения для контекста агентов и индексации. |
| `app/src/auth`, `app/src/server`, `crates/warp_server_client`, `crates/persistence` | Для локальной сборки добавлены заглушки `LocalAuthManager` и клиент с API авторизации. Миграции всё ещё создают таблицы и поля для агентов, моделей, MCP и облачных объектов. ИИ-поля есть в общих таблицах блоков и панелей. |
| Сборка, ресурсы и документация | Ресурсы для агентских навыков уже удалены из текущего дерева. В GUI-ресурсах остались баннеры и иконки, в упаковщиках — флаги NLD и Oz, в CI — отдельная проверка `agent_mode_evals` и задания для выпусков Agent CLI. Ресурсы встраиваются в бинарник и копируются отдельно. |
| Последний существующий `WarpOss.app` | Исполняемый файл весит 224 837 920 байт (214,4 МиБ). Поиск по нескольким семействам символов (`agent_sdk`, AI Assistant, классификаторы, Multi-Agent, auth) дал 263 строки. Это контрольный артефакт из предыдущей сборки. |

## Порядок удаления

### 1. Отвязать терминал от ИИ

- В `app/src/terminal`, `editor`, `pane_group`, `workspace`, `search` и `crates/warp_tui` оставить обычный ввод и обычный блок команды. Убрать AI-варианты состояний, действий, событий, панелей и блоков. Снять зависимость истории, подсветки, алиасов, подсказок и декораций от моделей ввода и ресурсов ИИ. Перенести только реально общие функции в существующие терминальные модули.
- Удалить автоматическое определение естественного языка, AI follow-up и отдельное AI-дополнение. Убрать планировщики классификации, ONNX-модели, токенизаторы, тесты, бенчмарки, флаги NLD, профили Cargo и правила Git LFS для этих моделей.
- Вычистить редактор, палитру команд, меню, настройки и поиск по ним, клавиши, slash-команды, контекстные меню, ссылки, вкладки, нотификации, onboarding и подсказки. Удалить также внутренние команды, debug-виджеты и тестовые точки входа. Обычное выделение, поиск по выводу, `Ctrl+R` и навигация по истории должны сохранить поведение.

### 2. Развязать CLI, PTY и Warpify

- Свести `warp_cli` к аргументам запуска и необходимым служебным командам. Сохранить запуск PTY worker, ripgrep worker, локальный IPC и минимальный удалённый сервер. Сверить родительский флаг, раннюю диспетчеризацию, восстановление процесса и автодополнение. Удалить dispatch и completion-ветки Agent/Oz, API keys, MCP, моделей, provider, runner, orchestration, расписаний, секретов, memory, задач и удалённых агентских окружений.
- Отделить Linux-помощник Warpify от Oz. Дать помощнику собственное имя, путь установки и идентификатор версии протокола. Проверять их при подключении, чтобы старый Oz на хосте не мог пройти проверку. Поставлять архив помощника из сборки форка. Сохранить перенос через SCP и обычную интерактивную SSH-сессию при отказе, тайм-ауте или отсутствии совместимого помощника. Оставить установленные компоненты оригинального Warp на месте.
- Удалить из `crates/remote_server/proto`, двустороннего dispatch, состояния, событий IPC и установочных скриптов контекст агента, навыки и векторную индексацию. Зарезервировать номера полей удалённых сообщений. Сохранить номера и семантику сообщений, нужных для PTY, оболочки, каталога и shell-дополнений. Проверить вложенные `zsh`, `bash`, `fish`, `ssh` с ProxyJump, существующий агент, выход и возврат ввода в родительскую оболочку.

### 3. Удалить реализации ИИ и их зависимости

- Удалить `app/src/ai`, `app/src/ai_assistant` и остатки ИИ в `coding_entrypoints`, code review, suggestions, voice, notebook/Drive, local-control и репозиторном поиске. Сверить импорты этих модулей в GUI, TUI, CLI, WASM, интеграционном раннере, примерах, бенчмарках и тестах.
- Удалить провайдеры LLM и BYOK, роутинг и тарифы моделей, ACP и MCP с OAuth, локальные и облачные задачи Oz, внешние agent hooks, Computer Use, диктовку, браузерные превью для агента, индексацию для RAG, эмбеддинги, память, skills, bash-права и sandbox для агента, traces/evals и события телеметрии ИИ. Общие текстовые редакторы, Git-операции, Markdown, файловые утилиты и средства редактирования логов сохраняются, если у них есть обычный локальный потребитель.
- Удалить специализированные crates и Git-зависимости, включая `ai`, `ai_types`, `mcp`, `computer_use`, `voice_input`, `input_classifier`, `natural_language_detection`, `warp_harness_usage`, `warp_multi_agent_client` и `warp_multi_agent_api`. Удалить зависимости таких подсистем, как `node_runtime`, `preview_proxy`, `managed_secrets*`, `isolation_platform`, генераторы протоколов, транспорт и секреты, когда устранены последние потребители. Для каждого оставшегося общего crate с подозрительным названием проверить обратное дерево и зафиксировать конкретного потребителя.
- Почистить workspace manifests, feature lists, `Cargo.lock`, overrides профилей, CI-кеши, Nix vendor и лицензии зависимостей. Удалить флаг `local_terminal` и ветки, которые возвращают AI/Auth в других каналах. Любая оставшаяся комбинация features собирает терминал.

### 4. Удалить вход и привязку к облаку Warp

- Удалить `AuthManager`, `AuthState`, локальные auth-заглушки, клиенты Firebase и Warp, OAuth/SSO, анонимный аккаунт, cookie/token refresh, device flow, API keys/IAP, биллинг, лимиты аккаунта, Login/Upgrade, обработчики callback URL, облачное разделение сессии, командные права и синхронизацию Drive. Убрать флаги входа, конфиги bootstrap и импорты из тестовых бинарников. Удалить обращения к связанной телеметрии, серверным экспериментам и назначениям моделей.
- Убрать GraphQL-контракты, сгенерированные клиенты/schema и web-маршруты, оставшиеся только ради этих сервисов. Сохранить локальные workflows и текстовые записи через их локальные модели. Схемы настроек генерируются без параметров аккаунта и ИИ. Проверить `serve-wasm` и web glue: удалить страницы для облачных объектов и сессий, оставить только поддерживаемые локальные сценарии рендера и воспроизведения. Проверка WASM включает загрузку локального пакета с заблокированными внешними запросами, поскольку браузер не поднимает системный PTY.
- Почистить `ChannelConfig`, launch modes, URI, облачные GitHub/Linear-интеграции, встроенные URL и необходимые только аккаунту секреты в CI. Проверить обновление форка отдельно. Приложение и вспомогательные процессы должны получать только артефакты форка. Локальный PTY и первый запуск после установки не требуют учетных данных.

### 5. Перейти на чистое локальное хранилище

- Создать схему для новых профилей напрямую. Не прогонять историю миграций с созданием таблиц ИИ и Warp Account. Удалить устаревшие миграции из сборки, Diesel-модели, persistence actions, кеши, сериализованные варианты AI-блоков и Agent-панелей.
- Для существующего профиля прочитать SQLite, настройки и локальные файлы из старого профиля в режиме только чтения. Перенести по разрешённому списку команды, обычные блоки, рабочие каталоги, окна, вкладки, панели, темы, горячие клавиши и локальные workflows. При чтении использовать положительный список переносимых записей. Не десериализовать ИИ-диалоги, токены, облачные идентификаторы и настройки провайдеров.
- Записать импорт транзакционно в отдельный профиль. Помечать его завершённым после успешной записи. Проверить чистый профиль, несколько исходных версий схемы, профиль с перемешанными обычными и агентскими данными, пустые панели, ошибку посередине и повторный запуск. Исходный профиль и ключи оригинального Warp должны остаться доступными.

### 6. Вычистить сборку и поставку

- Проверить все входы `script/run`, `script/run-tui`, Cargo, macOS, Linux, Windows, WASM, Nix, Docker и все каналы, оставленные в манифестах. Сверить `build.rs`, `.cargo`, `.gitattributes`, Git LFS, переменные сборки и профили. Убрать включение агента через инструкции/флаги канала, CI-матрицу и конфиги кешей. Убрать выпуск и загрузку Oz, Agent CLI, старых skills и AI dev-образов.
- Просмотреть оба каталога `app/assets/bundled` и `app/assets/async`, `resources`, шаблоны installers, updater, generated schema, CLI completions, примеры и fixtures. Проверить оба способа поставки ресурсов, копирование в архив и встраивание через макросы. Сборку вести в новом staging-каталоге. Сверить `.app` вместе с вложенными helper-бинарниками и Dock Tile, архив помощника, Linux-пакет, Windows installer и WASM/JS. Сохранить иконки терминала, нужные системные библиотеки и лицензии.
- Удалить из текущего дерева устаревшие продуктовые спецификации, скриншоты, инструкции и автоматизации разработки, которые поставляют или запускают удаляемый ИИ. Проверить `README`, `FAQ`, `specs`, `agents`, `.github`, `.warp`, `.agents`, `.claude`, `.mcp.json`, `skills-lock.json` и bootstrap. Сохранить необходимые лицензионные и авторские упоминания. Не трогать установленные глобальные инструменты разработчика.

### 7. Проверить результат перед выпуском

1. **Исходники.** Зафиксировать списки удаляемых crates, features, типов, CLI-команд, URL, ресурсов, миграций и генерируемых файлов. Проверять всё текущее дерево, включая hidden paths, `build.rs`, тесты и fixtures. Ввести проверку, которая падает при возврате удалённых зависимостей, флагов, команд и ресурсов. Каждое допустимое совпадение привязать к конкретному пути и причине. Например, `ssh-agent` относится к SSH, а названия старых полей могут встречаться в изолированных тестах импорта.
2. **Зависимости.** Для оставшихся GUI, TUI, WASM, CLI и SSH-helper проверить Cargo metadata и прямое и обратное дерево зависимостей со сборочными и тестовыми зависимостями. Повторить для сохранённых платформ и наборов features, включая default и максимальный поддерживаемый набор. `Cargo.lock` и Nix vendor не содержат удалённых пакетов. Локальные модули терминала не зависят от аккаунтных или агентских интерфейсов.
3. **Поведение.** Запустить проверки локального терминала и GUI/TUI/Web, миграции и SSH на чистом и ранее использованном хосте. С чистым профилем проверить запуск, историю, подсказки, многострочный ввод, блоки, Unicode/ANSI, `vim`, split/tab, поиск, настройки, восстановление и Dock Tile. Повторить при отключённой сети. Для сетевой проверки разрешить SSH до тестового хоста и подтвердить отсутствие попыток связи с сервисами Warp/Oz, провайдерами и Firebase, в том числе при заданных старых переменных окружения и старой cookie.
4. **Конечные файлы.** После всех изменений собрать релиз в чистом staging. Сверить linker map или символы до strip, секции, строки и динамические библиотеки. Проверить состав каждого архива и каждый вложенный исполняемый файл. Для WASM проверить импортируемые модули и встроенные данные. Отсутствие символов в stripped-файле само по себе результата не доказывает.
5. **Приёмка.** Приложить одну таблицу с результатами по каждому артефакту и сценарию. На Apple Silicon выдать проверенный подписанный `.app`, его размер и SHA-256. Отдельно указать размер основного файла, Dock Tile и ресурсов для сравнения с предыдущим артефактом. Соблюсти порядок проверок репозитория. Платформы проверять на фактической ревизии форка и записывать результаты отдельно.

Тотальное удаление подтверждается, когда проходят все проверки исходников, графа зависимостей, поведения и поставки. Любое найденное звено устраняется до выдачи финальной сборки в рамках соответствующего этапа этого плана.
