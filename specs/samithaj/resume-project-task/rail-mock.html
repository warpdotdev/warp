Rail design · v4

A row is the task. Whether it has a tab is a detail.

No second pane, no “Recent” header, no divider. Every row is a task; some happen to have a tab open right now. Clicking a live row activates its tab. Clicking a dormant row only previews it — last exchange, branch, message count — and nothing is created until you press Resume in new tab.

Naming cascade — first hit wins

  1. Explicit tab rename — pane_group.custom_title, persisted. Live rows only.
  2. ai-title from the transcript — Claude writes AI-generated titles (and /rename values) straight into the JSONL. Present on 87% of sessions with 6+ messages, 100% at 20+. The workhorse.
  3. Session-memory summary — ~/.claude/projects/<enc-cwd>/<uuid>/session-memory/summary.md. Borrowed from Orbit; reject unfilled templates.
  4. Latest user prompt — live sessions, from the event stream.
  5. First user prompt from the transcript — bounded 256 KB head read, mtime-memoised. Works for dormant rows.
  6. Agent + short id — Claude · 998add3f. Last resort, never blank.
  7. Truncated cwd — today’s behaviour. Rejected outright: it is what makes five rows read identically.
  8. Permission summary — a status blurb wiped on the next prompt, not a name.
  9. Claude’s auto name <dir>-<2hex> — e.g. poa-agent-0f. Junk; Orbit rejects it too.

Never reuse another project's pane

A pane's project comes from its cwd, so restoring into a pane belonging to a different project would silently re-bucket that tab. ActivePane/SplitPane placement is only legal inside the target project — otherwise fall back to a new tab.

Preview before commit

Selecting a dormant row has no side effect. Creating a tab is a real action, so it needs its own deliberate one — otherwise a misidentified row leaves a stray tab to close.

Dormant rows never reach the tab bar

They are absent from visible_tab_indices, so they never appear on top and never join cycle_next/cycle_prev.

A quiet project can still have rows

project_status reads open tabs only — a project whose rows are all dormant shows no status dot. Correct, but worth seeing.

Five dormant rows, then “N more”

Dormant rows must never bury live ones. Live first in tab order, dormant after by last-seen.
